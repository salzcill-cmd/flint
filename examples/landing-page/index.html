Features

Why developers choose Flint

A JavaScript framework built around one idea: you write less code, and it runs faster.

⚡

Fine-Grained Reactivity

Signals track dependencies automatically. When state changes, only the exact DOM nodes that depend on it update. No virtual DOM diffing, no reconciliation overhead.

🎯

Zero Overhead

No runtime cost from reconcilers. Components compile to direct DOM updates — O(1) regardless of app size.

🛡️

Type Safe

First-class TypeScript with fully inferred types. Catch errors at compile time, not in production.

🔥

Blazing Fast

Benchmark-proven performance. Your app stays fast as it grows because updates are always constant-time.

🧩

Composable

Build complex UIs from simple, reusable pieces. Mix signals, effects, and components naturally.

📦

Tiny Bundle

Ship less JavaScript to your users. Flint's runtime is minimal and tree-shakable.

Simple API

Write components,
not boilerplate

Your component function runs once. After that, only the signals you read get tracked. No dependency arrays, no optimization tricks — the framework handles it. 

import { render, state, computed, effect } from 'flint'

function Counter() {
  const count = state(0)
  const doubled = computed(() => count() * 2)

  effect(() => {
    document.title = `Count: ${count()}`
  })

  return (
    <div>
      <p>Count: {count()}</p>
      <p>Doubled: {doubled()}</p>
      <button onClick={() => count.set(c => c + 1)}>
        +1
      </button>
    </div>
  )
}

render(Counter, '#app')

function Counter() {
  const [count, setCount] = useState(0)
  const doubled = useMemo(() => count * 2, [count])

  const increment = useCallback(() => {
    setCount(c => c + 1)
  }, [])

  return (
    <div>
      <p>Count: {count}</p>
      <p>Doubled: {doubled}</p>
      <button onClick={increment}>
        +1
      </button>
    </div>
  )
}

FAQ

Frequently asked questions

Flint uses fine-grained signals instead of a virtual DOM. When state changes, only the exact DOM nodes that depend on that state update — no diffing, no reconciliation. This means O(1) updates regardless of app size, and you never need useMemo or useCallback.
Yes. Flint can be adopted incrementally. You can start using Flint components alongside your existing React or Vue codebase, then migrate as you go. The framework is designed for gradual adoption.
Absolutely. Flint is written in TypeScript and provides full type inference for signals, computed values, stores, and component props. No extra type annotations needed — everything is inferred.
Flint v4.0 is stable and used in production. The core reactivity system, router, store, and form handling are all battle-tested. The framework follows semver and maintains backward compatibility within major versions.
